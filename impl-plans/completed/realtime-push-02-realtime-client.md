## Intent and context

Create `@flying-mail/realtime-client`, a zero-dependency TypeScript package
that implements the client side of `graphql-transport-ws` for a single
`mailEvents` subscription, with reconnect, cursor resume, resync and
re-auth handling. `apps/web` (plan 06) and `apps/cli` (plan 07) consume it.

This plan is also the **only** plan that links the new workspace package
into `apps/web` and `apps/cli` (`package.json` plus a one-time `bun
install`). Wave 2 can then import it.

## Non-goals

- No `graphql-ws` or any other third-party dependency (design D9).
- No UI, no CLI command, no server code.
- Must not import any other `@flying-mail/*` package.

## Behaviour (design 10.2), the points a careless implementation gets wrong

1. **Connect.**
   - `webSocketFactory(url, "graphql-transport-ws")`. The default uses
     `new WebSocket(url, "graphql-transport-ws")` from `globalThis`.
   - Send `connection_init` with `await connectionParams()`, evaluated on
     **every** attempt (re-auth).
   - No `connection_ack` within 10 s: close and retry.
2. **Subscribe.**
   - After ack, send `subscribe` with a fresh id (`"1"`, `"2"`, ... per
     socket).
   - Payload: `{ query, variables: { scope: scope ?? null, after: lastCursor } }`.
   - `lastCursor` is the latest processed cursor: an event's or LIVE's. It
     is never the original `initialCursor` once anything newer was seen.
3. **`next`.**
   - Read `payload.data.mailEvents`.
   - Missing `cursor` or `type`: treat as fatal `onFatal({code: 4400})`.
     This is a client bug.
   - Dedupe: if `compareCursors(cursor, lastCursor)` is `"older"` or
     `"same"`, drop the event silently.
   - Otherwise: update `lastCursor`, call `onCursor`, then `onEvent`.
   - When the type is `LIVE`, also set status `live` and reset the backoff
     attempt to 0.
4. **`error` for the current subscription id.**
   - If any error has `extensions.code === "RESYNC_REQUIRED"`: set
     `lastCursor = null`, call `onCursor(null)` and `onResync()`, and
     resubscribe immediately on the same socket with a new id and no
     `after`.
   - Any other error: `onFatal({ code: 4400, reason })`, stop.
5. **Server `complete`:** close the socket with 1000 and reconnect with
   backoff.
6. **Heartbeat.**
   - Every 25 s send exactly `{"type":"ping"}`, the literal string. The
     Durable Object auto-response only matches it byte for byte.
   - No `pong` (or any message) within 10 s after a ping: close locally and
     reconnect.
   - Answer a server `ping` with `{"type":"pong"}`.
7. **Close classification.**
   - `4401`: status `offline`, call `onAuthFailure()`, **stop** (no
     retry). The caller decides whether to `start()` again.
   - `4403`, `4400`, `4409`, `4429`, `1009`: status `offline`, call
     `onFatal`, stop.
   - Everything else, including `1006` and an error before open: status
     `reconnecting`, and retry after
     `random() * min(30000, 1000 * 2 ** attempt)` ms, then `attempt++`.
8. **`stop()`** clears every timer, closes with 1000, and never reconnects.
   Calling `start()` after `stop()` works again.
9. **Status sequence:** `connecting` on the first attempt, `reconnecting` on
   later ones, `live` on LIVE.

Cursor helper (`cursor.ts`): split on the first `.`.

- Same epoch: compare the numeric seq.
- Epoch differs: `"different-epoch"`, and the client treats the new cursor
  as newer.
- Unparsable: treat as `"different-epoch"`; never throw.

## Pitfalls

- Never put the API key or cookie in the URL. `connectionParams` is the
  only credential path.
- Do not reuse the original `after` on reconnect. This is the exact
  `graphql-ws` behaviour the design rejects.
- Timers must be cleared on every socket close, or fake-timer tests leak
  reconnects.
- Keep each file under 400 lines. Do not use the `WebSocket` global in
  tests.

## Tests (vitest fake timers, a scripted fake socket)

- Happy path:
  - init sent with params, then ack
  - subscribe with `after: null`
  - LIVE, then status `live`, `onCursor`
  - an event, then `onEvent`
- A drop before LIVE (close 1006): reconnect delay within
  `[0, 1000 * 2^attempt]` with `random = () => 1`. Delays grow, and are
  capped at 30000.
- LIVE resets the attempt counter: the next delay is `<= 1000`.
- Resume: events up to `e.5`, then close 1006, then the new subscribe has
  `variables.after === "e.5"`. `connectionParams` was called twice.
- Duplicate guard: the server replays `e.4` and `e.5` after a resume with
  `after=e.5`. Both are dropped and `onEvent` is not called.
- RESYNC: an `error` with `RESYNC_REQUIRED`, then `onResync`,
  `onCursor(null)`, and a new subscribe on the same socket without
  `after`.
- 4401: `onAuthFailure` once, no reconnect timer scheduled.
- 4403 and 4409: `onFatal`, no reconnect.
- Pong timeout: after 25 s a ping is sent; no pong for 10 s closes the
  socket and schedules a reconnect.
- The ping frame is exactly `{"type":"ping"}`.
- `stop()` during a pending reconnect: no further factory calls.
- Ack timeout: 10 s without ack closes and retries.
- `compareCursors`: older, same and newer within one epoch; a different
  epoch; malformed input.
